# Финальная диагностика 403 Forbidden на beta

## Текущая ситуация

✅ **Правильно настроено:**
- Путь API: `/v1/payment` ✅
- Окружение: `beta` ✅
- URL: `https://beta.api.acquiring.averspay.kg/v1/payment` ✅

❌ **Проблема:**
- 403 Forbidden от Финика

## Что проверить в логах

На сервере выполните:

```bash
pm2 logs finik-api --lines 300 | grep -A 100 "Canonical String"
```

Ищите каноническую строку. Она должна быть в формате:
```
post
/v1/payment
host:beta.api.acquiring.averspay.kg&x-api-key:...&x-api-timestamp:...
{"Amount":1,"CardType":"FINIK_QR",...}
```

## Возможные причины

### 1. Неправильные credentials для beta (наиболее вероятно)

**Проблема:** Используются те же credentials, что и для production.

**Решение:** 
- API Key для beta может отличаться от production
- Account ID для beta может отличаться от production
- Нужны отдельные credentials для beta окружения

**Проверка:**
```bash
cd /var/www/finik
cat .env | grep FINIK
```

### 2. Публичный ключ не зарегистрирован в beta

**Проблема:** Публичный ключ зарегистрирован только для production, но не для beta.

**Решение:** 
- Отправьте публичный ключ (из файла `publ1`) в поддержку Финика
- Укажите, что это для **beta** окружения
- Попросите зарегистрировать ключ в beta

### 3. Аккаунт не активирован в beta

**Проблема:** Аккаунт активирован только в production, но не в beta.

**Решение:** 
- Свяжитесь с поддержкой Финика
- Попросите активировать аккаунт в beta окружении

### 4. Неправильная подпись (менее вероятно)

Если на production подпись работала (был `status=failed`, а не 403), то подпись правильная.

Но для beta может быть другой формат. Проверьте каноническую строку в логах.

## Что делать

### Шаг 1: Проверьте каноническую строку

```bash
pm2 logs finik-api --lines 500 | grep -B 5 -A 50 "Canonical String"
```

Убедитесь, что:
- Host правильный: `beta.api.acquiring.averspay.kg`
- Путь правильный: `/v1/payment`
- Заголовки в правильном порядке: `host:` первый, затем `x-api-*`

### Шаг 2: Свяжитесь с поддержкой Финика

Предоставьте им:

1. **AccountId:** `9c247f61-d1da-422b-93e5-9a1e9d9a47f3`
2. **Первые 10 символов API Key:** `68WSqzVmob`
3. **Окружение:** `beta`
4. **URL запроса:** `https://beta.api.acquiring.averspay.kg/v1/payment`
5. **Каноническую строку** (из логов)
6. **Публичный ключ** (из файла `publ1`)

Попросите проверить:
- ✅ Правильность AccountId и API Key для **beta** окружения
- ✅ Активирован ли аккаунт в **beta**
- ✅ Зарегистрирован ли публичный ключ в **beta**
- ✅ Соответствует ли формат подписи их требованиям для beta

### Шаг 3: Получите правильные credentials для beta

Если у вас нет отдельных credentials для beta:
- Попросите у поддержки Финика тестовые credentials для beta
- Или используйте production окружение (но там была проблема с `status=failed`)

## Сравнение с production

**Production:**
- Подпись правильная ✅
- Запрос доходит до Финика ✅
- Платеж создается, но отклоняется (`status=failed`) ❌
- **Вывод:** Credentials правильные, но аккаунт/настройки неправильные

**Beta:**
- Подпись правильная (предположительно) ✅
- Запрос отклоняется до обработки (403 Forbidden) ❌
- **Вывод:** Credentials неправильные для beta, или аккаунт не активирован в beta

## Рекомендация

Скорее всего проблема в том, что:
1. Используются production credentials для beta окружения
2. Или аккаунт не активирован в beta
3. Или публичный ключ не зарегистрирован в beta

**Решение:** Свяжитесь с поддержкой Финика и получите правильные credentials для beta, или активируйте аккаунт в beta.
