# Решение проблемы с ключом через файл

## Проблема

Если ключ в `.env` файле не работает из-за проблем с переносами строк, используйте файл.

## Решение: Использовать файл вместо переменной окружения

### Шаг 1: Создайте файл с ключом

Создайте файл `finik_private.pem` в корне проекта (там же где `server.js`):

```bash
# Если у вас уже есть ключ, скопируйте его:
cp /path/to/your/finik_private.pem ./finik_private.pem

# Или сгенерируйте новый:
openssl genrsa -out finik_private.pem 2048
```

### Шаг 2: Убедитесь, что файл правильный

Файл должен выглядеть так:

```
-----BEGIN PRIVATE KEY-----
MIIEvQIBADANBgkqhkiG9w0BAQEFAASCBKcwggSjAgEAAoIBAQC...
(много строк)
...
-----END PRIVATE KEY-----
```

### Шаг 3: Удалите FINIK_PRIVATE_PEM из .env (опционально)

Теперь можно удалить `FINIK_PRIVATE_PEM` из `.env`, так как ключ будет читаться из файла:

```env
FINIK_API_KEY=your_api_key
FINIK_ACCOUNT_ID=your_account_id
FINIK_ENVIRONMENT=production
# FINIK_PRIVATE_PEM больше не нужен, если используется файл
```

### Шаг 4: Проверьте права доступа (Linux/Mac)

```bash
chmod 600 finik_private.pem  # Только владелец может читать
```

### Шаг 5: Добавьте файл в .gitignore

**ВАЖНО:** Никогда не коммитьте приватный ключ в Git!

```bash
echo "finik_private.pem" >> .gitignore
```

## Альтернатива: Указать другой файл

Если хотите использовать другой файл, установите переменную:

```env
FINIK_PRIVATE_PEM_FILE=/path/to/your/key.pem
```

## Преимущества использования файла

1. ✅ Нет проблем с переносами строк в .env
2. ✅ Легче управлять ключами
3. ✅ Можно использовать разные ключи для разных окружений
4. ✅ Безопаснее (можно установить строгие права доступа)

## Проверка

После создания файла запустите:

```bash
npm run check-key
```

Должно показать:
```
✅ Ключ загружен из файла: finik_private.pem
✅ Ключ успешно использован для подписи!
```

## Если все еще не работает

1. Проверьте, что файл существует: `ls -la finik_private.pem`
2. Проверьте содержимое: `head -n 1 finik_private.pem` (должно быть `-----BEGIN PRIVATE KEY-----`)
3. Проверьте права: `chmod 600 finik_private.pem`
4. Убедитесь, что файл в корне проекта (там же где server.js)
